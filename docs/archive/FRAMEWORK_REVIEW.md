## 需要修改的 4 项

### 1. [P1] 工程车切回底盘模式仍会重新提交机械臂旧目标

位置：工程车 `App/Vehicle/app_vehicle.c:74–89`，以及 `App/Arm/app_arm.c:175` 起的周期更新。

`app_vehicle_update()` 只在输出未允许或遥控指针为空时停止机械臂。MANUAL 分支之外，仍无条件调用 `app_arm_update()`。机械臂内部保存关节目标，update 会把这些目标再次写入本周期请求；调度器开头清空 staging 并不能清掉这一层保存的目标。

静态复现路径：关节配置齐全 → 在机械臂调试模式通过 setter 设置一个关节目标 → 保持使能并切换到 `APP_MODE_CHASSIS` → `app_arm_update()` 仍提交 POSITION 请求。同样没有针对遥控离线的本层防御；炮台车 Vehicle 实现则已对其他模式显式 stop。

修改要求：定义工程车支持的专有模式，其他模式及离线输入显式停止/清目标并返回；在需要失效的模式转换时取消旧目标和旧任务。仅清本周期电机请求不够。

回归用例：手动关节有目标时切到 CHASSIS、DISABLED、UNKNOWN 或离线，下一次提交没有机械臂请求；再次进入手动模式时不自动恢复旧目标。保留合法手动请求的正常路径。

### 2. [P2] 故障置位后没有合法的活动故障清除路径

位置：两车 `App/Protection/app_protection.c:138–166` 及其公开头文件。

`app_protection_raise()` 同时 OR 入 `active_faults` 和 `latched_faults`。`clear_latched()` 在 active 非零时必定拒绝，而 active 仅在 init 中清零，没有故障源恢复接口或每周期重新计算机制。`app_protection_report()` 返回 const 指针，也不能作为合法修改入口。因此一次 raise 后，即使故障原因消失，遥控复位也不能恢复；当前模块 README 中“清 active 后再清锁存”的步骤无法通过现有接口完成。

修改要求：分别表达“故障源仍然存在”和“历史故障仍被锁存”。为受控监督逻辑提供更新/解除活动故障的办法，保留原因消失后仍需显式复位的要求，禁止使用重新初始化整个保护模块来掩盖问题。

回归用例：raise → active/latched 均置位；原因仍存在时复位失败；原因解除后仍锁存并禁止输出；显式复位后才允许重新评估配置、输入、设备及使能条件。

### 3. [P2] 遥控与姿态的“快照拷贝”没有保证并发一致性

位置：两车 `App/Remote/app_remote.c:150–151`、`app_remote_update()`、`app_remote_get_snapshot()`；`App/Attitude/app_attitude.c:72–74` 与其读取接口。

接口说明允许后续接收任务或中断调用 ingest，但实现仅使用普通结构体赋值，无临界区、互斥或其他一致性机制。多字段结构体的拷贝不是原子操作。控制任务可能读取到“旧通道 + 新时间戳”，或多个姿态字段来自不同帧。getter 拷贝一次结构体也不会自动解决读写交错。

修改要求：明确各入口在哪个上下文调用，采用适合该上下文的一致性机制；例如在短临界区内发布/复制完整原始样本，控制任务使用周期局部副本。中断路径不能使用阻塞互斥。公共模块两车同步。

回归用例：交替发布两帧字段显著不同的数据，控制侧每次只能读到完整的某一帧，字段与时间戳匹配；模拟发布和读取交错，不出现混合快照。没有输入适配的当前固件尚不会触发这个竞态，但接口接入前需解决。

### 4. [P2] 无效姿态样本会被强制标为有效

位置：两车 `App/Attitude/app_attitude.c:59–75`。

`app_attitude_ingest()` 只检查指针和六个浮点数是否有限，没有检查输入的 `sample->valid`，随后无条件设置 `g_snapshot.valid=true`、状态为 OK。传入一个所有数值为 0、`valid=false` 的样本，就会把无测量数据变成“有效零姿态”。这与头文件中 valid=false 表示数值无意义的约定冲突。

修改要求：明确无效帧如何使模块降级；不能覆盖 valid=false 为 true，也不能在收到传感器无效通知后继续把旧样本标成新鲜有效。保留尚未实现 IMU 的真实状态。

回归用例：初始化后提交 valid=false 的有限值样本，不得变成 OK/有效；先提交有效样本再提交无效样本，应按约定使健康状态降级；NaN/Inf 路径继续被拒绝。

## 后续接硬件时仍需完成的项目

原有驱动问题没有因本次搭架构而修复：电机构造无限等待、CAN 接收指针/索引校验、队列载荷生命周期、发送失败处理及中断资源初始化顺序，仍按基线记录处理。

功率接口目前只限制归一化电流/电压代理量，速度/位置请求不受该预算约束。当前所有机构实际生成的请求是速度或位置；因此后续不能声称整车已有功率限制。功率策略未完成时，需要明确的输出门控或经过核实的驱动层限幅方案。

遥控原始值目前写有 1500/500 的归一化假设，且尚无实际通道/开关映射。接入 DR16 前必须对照本地协议手册核验数据格式与刻度，不能仅打开 mapping_valid 就认为映射已完成。本轮未核对该 PDF 的具体数值。
